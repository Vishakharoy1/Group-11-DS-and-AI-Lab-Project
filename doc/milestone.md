# 1. Dataset Description and Preprocessing

## 1.1 Overview
The effectiveness of a deep learning model for AI-generated face detection is largely determined by the quality, diversity, and representativeness of the training dataset. A robust dataset should include both authentic human face images and synthetic images generated using state-of-the-art generative models. Training on diverse datasets enables the model to learn discriminative facial features while improving its ability to generalize across images generated by different AI models.

To achieve these objectives, this project utilized three publicly available datasets obtained from Kaggle. The primary dataset consisted of real human face images from the Flickr-Faces-HQ (FFHQ) dataset and AI-generated face images created using Stable Diffusion. To further enhance the diversity of synthetic images and improve cross-domain generalization, an additional dataset containing images generated using Nano Banana 2.0 was incorporated into the training pipeline. The combination of these datasets provided a comprehensive collection of real and AI-generated faces, allowing the model to learn generalized representations rather than generator-specific artifacts.

## 1.2 Datasets Used

### 1.2.1 Real vs AI Generated Faces Dataset
The primary dataset used in this project was the Real vs AI Generated Faces Dataset, which is publicly available on Kaggle. This dataset contains two categories of facial images:

* Real human face images collected from the Flickr-Faces-HQ (FFHQ) dataset.
* AI-generated face images produced using modern image generation techniques.

The FFHQ dataset is one of the most widely used benchmark datasets for facial analysis because it contains high-quality images with significant diversity in age, gender, ethnicity, facial expression, illumination, pose, and background. Such diversity enables the model to learn robust facial representations while reducing the possibility of overfitting to specific demographic characteristics.

Although the original dataset contains approximately 70,000 real face images, only 15,000 real images were selected for training in order to maintain computational efficiency while preserving sufficient variability within the dataset.

**Reasons for selecting the dataset include:**
* High-resolution facial images with minimal visual artifacts.
* Large diversity in facial appearance and imaging conditions.
* Well-established benchmark dataset for face-related computer vision tasks.
* Suitable source of authentic human face images for binary classification.

### 1.2.2 Stable Diffusion Dataset
To represent AI-generated faces, the project utilized the Stable Diffusion Dataset, which contains facial images generated using the Stable Diffusion diffusion model.

Recent diffusion models produce significantly more realistic images than earlier Generative Adversarial Networks (GANs). Consequently, detecting synthetic images generated using diffusion models is considerably more challenging. Including Stable Diffusion images during training enables the model to learn subtle inconsistencies present in synthesized facial structures, textures, illumination, and fine-grained details.

A total of 9,001 AI-generated face images from this dataset were included in the primary training dataset.

**Reasons for selecting the dataset include:**
* Represents modern diffusion-based image generation.
* Contains highly realistic synthetic facial images.
* Provides challenging examples for model training.
* Improves the detector's ability to recognize subtle AI-generated artifacts.

### 1.2.3 AI Image with Nano Banana 2.0 vs Real Image Dataset
Although models trained on a single image generator often achieve excellent performance on similar images, their performance may decrease when evaluated on images produced by previously unseen generators. This limitation is commonly referred to as cross-domain generalization.

To improve the robustness of the detector, the AI Image with Nano Banana 2.0 vs Real Image Dataset was incorporated into the training process. This dataset contains additional real and AI-generated images produced using the Nano Banana 2.0 image generation model.

Instead of reserving this dataset exclusively for testing, its predefined training, validation, and testing subsets were merged with the corresponding partitions of the primary dataset. This strategy substantially increased the diversity of both authentic and synthetic facial images encountered during training.

**The Nano Banana dataset contributed:**
* **31,999** training images
* **4,000** validation images
* **4,000** testing images

The inclusion of this dataset enhanced the model's ability to generalize across different image-generation techniques while reducing overfitting to Stable Diffusion-specific artifacts.

**Reasons for selecting the dataset include:**
* Improves cross-domain generalization.
* Increases dataset diversity.
* Reduces dependence on a single image generator.
* Provides additional validation and testing samples for more reliable performance evaluation.

## 1.4.1 Face Detection and Alignment

The first stage of preprocessing involved detecting the facial region within each image using the **RetinaFace** face detection algorithm. RetinaFace is a robust single-stage face detector capable of accurately localizing faces under challenging conditions, including variations in pose, illumination, occlusion, and facial expression.

Unlike traditional face detectors that only predict a bounding box, RetinaFace also estimates five facial landmarks corresponding to the eyes, nose, and mouth corners. These landmarks were used to align faces before cropping, ensuring that facial features occupied consistent spatial locations across the dataset.

**Face alignment offers several advantages:**
* Reduces variations caused by head tilt and rotation.
* Ensures consistent positioning of facial features.
* Removes unnecessary background information.
* Enables the model to focus on intrinsic facial characteristics instead of irrelevant image content.

> **Note:** If RetinaFace was unable to detect a face in an image, a center-crop strategy was employed as a fallback to avoid discarding potentially useful samples.

---

## 1.4.2 Face Cropping and Image Resizing

After face detection, the detected facial region was cropped from the original image to eliminate unnecessary background information. Background elements such as buildings, vegetation, furniture, or clothing may introduce biases during training and are generally unrelated to the authenticity of the face itself.

The cropped facial region was subsequently resized to **224 × 224 pixels**, which is the standard input resolution required by the MobileNetV3-Large architecture. Standardizing image dimensions ensures that all samples have a consistent spatial resolution, enabling efficient batch processing during training.

Resizing all images to a fixed resolution also reduces computational complexity and GPU memory usage while preserving sufficient facial detail for feature extraction.

---

## 1.4.3 Image Normalization

Following resizing, each image was normalized using the ImageNet mean and standard deviation. Since the MobileNetV3-Large backbone was initialized with ImageNet-pretrained weights, applying the same normalization scheme ensures compatibility between the input distribution and the distribution used during pre-training.

Normalization transforms pixel values into a standardized range, which provides several advantages:
* Faster convergence during optimization.
* Improved numerical stability.
* Reduced sensitivity to lighting variations.
* Better transfer learning performance.

### Normalization Parameters

| Parameter | Value |
| :--- | :--- |
| **Mean** | `(0.485, 0.456, 0.406)` |
| **Standard Deviation** | `(0.229, 0.224, 0.225)` |

These values are widely adopted for models pretrained on the ImageNet dataset.

# 1.5 Data Augmentation

Although the combined dataset contained a large number of images, the model could still become sensitive to specific image characteristics such as orientation, illumination, compression level, or camera quality. To improve generalization and reduce overfitting, on-the-fly data augmentation was applied during training.

Unlike offline augmentation, where transformed images are permanently stored on disk, on-the-fly augmentation generates a different transformed version of an image every time it is loaded during training. This effectively increases the diversity of the training data without increasing storage requirements.

The following augmentation techniques were employed:

### 1.5.1 Random Resized Crop
Random Resized Crop randomly selects a region of the input image and resizes it back to the required input size.
* **Purpose:** Simulates variations in image framing, improves robustness to different face scales, and prevents the model from relying on fixed facial positions.

### 1.5.2 Horizontal Flip
Horizontal flipping mirrors an image across the vertical axis with a predefined probability.
* **Purpose:** Generates left-right facial variations, increases dataset diversity, and improves invariance to facial orientation. Since human faces are approximately symmetrical, horizontal flipping does not alter class labels while providing additional training examples.

### 1.5.3 Color Jitter
Color Jitter randomly modifies image brightness, contrast, saturation, and hue.
* **Purpose:** Simulates different illumination conditions, improves robustness to camera settings, and reduces sensitivity to color variations. This prevents the model from associating image color characteristics with a particular class.

### 1.5.4 JPEG Compression
JPEG Compression introduces compression artifacts commonly encountered in images downloaded from social media platforms or messaging applications.
* **Purpose:** Simulates real-world image degradation, improves robustness against compressed images, and reduces dependence on high-quality image details. Since many deepfake images are shared online after multiple compression stages, this augmentation improves practical deployment performance.

### 1.5.5 Gaussian Blur
Gaussian Blur smooths the image by reducing high-frequency information.
* **Purpose:** Simulates camera defocus, represents motion blur, and prevents over-reliance on extremely fine texture details. Training with blurred images enables the detector to maintain performance even when image quality is degraded.

### 1.5.6 Gaussian Noise
Gaussian Noise randomly perturbs pixel intensities.
* **Purpose:** Simulates sensor noise and low-light conditions, improves robustness to noisy images, and prevents overfitting to perfectly clean training samples. Exposure to noisy images encourages the model to focus on meaningful facial structures rather than individual pixel values.

# 2. Model Architecture

## 2.1 Overview

The proposed deepfake detection system is based on **MobileNetV3-Large**, a lightweight convolutional neural network (CNN) pre-trained on the ImageNet dataset. The model was selected because it offers an excellent balance between classification accuracy, computational efficiency, and inference speed. Compared to larger CNN architectures such as ResNet-50 and EfficientNet-B4, MobileNetV3-Large requires significantly fewer parameters and computational resources while maintaining competitive performance. These characteristics make it suitable for both research applications and deployment on resource-constrained devices.

Instead of training the network from scratch, transfer learning was employed by initializing the model with ImageNet pre-trained weights. The original classification layer, designed for 1,000 ImageNet classes, was replaced with a custom fully connected layer consisting of two output neurons corresponding to the binary classes:

* **Class 0:** Real Face
* **Class 1:** AI-generated Face

The overall architecture used in this project is illustrated in **Figure 2.1**.

## 2.2 Architecture Components

The MobileNetV3-Large architecture consists of several interconnected layers that progressively extract discriminative facial features from the input image. The major components are described below.

### 2.2.1 Input Layer
The network accepts an RGB facial image of size **224 × 224 × 3**. All input images are preprocessed through face detection, alignment, resizing, normalization, and data augmentation before being passed to the network.

### 2.2.2 Initial Convolution Layer
The first layer of the network is a standard convolutional layer that extracts low-level visual features such as edges, corners, textures, and color gradients. These low-level features form the foundation for learning increasingly complex facial representations in the subsequent layers.

### 2.2.3 MobileNetV3-Large Backbone
The backbone is responsible for extracting hierarchical features from the input image. MobileNetV3-Large employs a series of **Mobile Inverted Bottleneck Convolution (MBConv)** blocks that efficiently learn spatial and semantic information while minimizing computational complexity.

The backbone combines several efficient design elements:
* **Depthwise Separable Convolutions:** Reduce the number of computations by separating spatial filtering from channel-wise feature combination.
* **Inverted Residual Bottleneck Blocks:** Improve feature extraction while maintaining a lightweight architecture.
* **Squeeze-and-Excitation (SE) Modules:** Apply channel-wise attention by emphasizing informative features and suppressing less relevant ones.
* **Hardswish Activation Function:** Improves nonlinear feature representation while remaining computationally efficient.

These components enable the model to learn subtle facial textures and structural inconsistencies that distinguish AI-generated faces from authentic images.

### 2.2.4 Global Average Pooling Layer
After feature extraction, a **Global Average Pooling (GAP)** layer is applied to reduce the spatial dimensions of the feature maps. Instead of flattening the entire feature map, GAP computes the average activation of each feature channel, producing a compact feature vector.

**This approach offers several advantages:**
* Reduces the number of trainable parameters.
* Minimizes the risk of overfitting.
* Improves computational efficiency.
* Preserves high-level semantic information.

### 2.2.5 Classification Layer
The original MobileNetV3-Large classifier was designed for 1,000-class ImageNet classification. For this project, the classifier was replaced with a custom fully connected layer containing two output neurons corresponding to the binary classes.

The final output is passed through a **Softmax** function to obtain class probabilities, and the class with the highest probability is selected as the prediction.

---

## 2.3 Transfer Learning Strategy

To efficiently adapt the pretrained model to the deepfake detection task, a two-stage transfer learning strategy was adopted:

1. **Stage 1: Feature Extraction**  
   During the first stage, all layers of the MobileNetV3-Large backbone were frozen, and only the newly added classification layer was trained. This allowed the model to adapt the classifier to the new binary classification task while retaining the generic visual features learned from the ImageNet dataset.

2. **Stage 2: Fine-Tuning**  
   After the classifier had converged, the final 25% of the backbone layers were unfrozen and fine-tuned using a lower learning rate. Fine-tuning enabled the higher-level feature representations to adapt specifically to facial characteristics associated with AI-generated images while preserving previously learned low-level features.

This two-stage training strategy improved convergence stability and enhanced the model's ability to discriminate between real and synthetic facial images.

MobileNetV3-Large was selected because it provides an effective balance between accuracy and computational efficiency. Its lightweight design enables faster training and inference while maintaining strong feature extraction capabilities. The integration of transfer learning, attention mechanisms, and a two-stage fine-tuning strategy allowed the model to achieve high classification performance on AI-generated face detection without the computational overhead associated with larger CNN architectures.

## 3.4 Loss Function
The model was trained using the `CrossEntropyLoss` function, which is the standard loss function for multi-class and binary image classification problems.

`CrossEntropyLoss` compares the predicted probability distribution with the actual class labels and computes the prediction error for each training sample. During optimization, the objective is to minimize this loss, enabling the model to produce increasingly accurate predictions.

This loss function was selected because it provides stable optimization behaviour and is well suited for neural networks that produce probability distributions through the Softmax activation function.

---

## 3.5 Optimizer
The network parameters were optimized using the **AdamW** optimizer.

AdamW is an improved version of the Adam optimizer that separates weight decay from the gradient update process. This modification improves regularization and reduces overfitting, resulting in better generalization performance.

Different learning rates were employed during the two training stages to ensure stable convergence.

**Table 3.3: Optimizer Configuration**

| Parameter | Value |
| :--- | :--- |
| **Optimizer** | AdamW |
| **Learning Rate (Stage 1)** | 3 × 10⁻⁴ |
| **Learning Rate (Stage 2)** | 1 × 10⁻⁵ |
| **Weight Decay** | 1 × 10⁻⁴ |

A relatively higher learning rate was used during the initial training stage to quickly adapt the classification layer, while a smaller learning rate was adopted during fine-tuning to avoid disrupting the pretrained backbone features.

---

## 3.6 Learning Rate Scheduler
To improve optimization stability, the **CosineAnnealingLR** scheduler was employed during training.

The scheduler gradually decreases the learning rate following a cosine decay pattern. Initially, the model performs larger parameter updates, enabling faster learning. As training progresses, the learning rate decreases smoothly, allowing the optimizer to make smaller refinements that improve convergence and reduce oscillations near the optimum solution.

Using a cosine annealing schedule helped stabilize training and contributed to improved validation performance.

---

## 3.7 Training Strategy
A two-stage transfer learning strategy was adopted to efficiently adapt the pretrained MobileNetV3-Large model to the AI-generated face detection task.

### Stage 1: Feature Extraction
During the first stage, the entire MobileNetV3-Large backbone was frozen, and only the newly added classification layer was trained. The objective of this stage was to adapt the classifier to the binary classification task while preserving the generic visual representations learned from the ImageNet dataset.

* **Frozen Backbone:** Yes
* **Trainable Layers:** Classification Head
* **Epochs:** 3
* **Learning Rate:** 3 × 10⁻⁴

### Stage 2: Fine-Tuning
After the classifier converged, the final 25% of the backbone layers were unfrozen and fine-tuned. Instead of updating the entire network, only the higher-level feature extraction layers were allowed to learn task-specific facial representations. This approach improved model adaptation while minimizing the risk of catastrophic forgetting.

* **Frozen Backbone:** No
* **Fine-tuned Layers:** Last 25% of Backbone
* **Epochs:** 7
* **Learning Rate:** 1 × 10⁻⁵

The combined two-stage strategy allowed the model to leverage pretrained ImageNet features while learning the subtle differences between authentic and AI-generated facial images.

---

## 3.8 Mixed Precision Training
To improve computational efficiency, **Automatic Mixed Precision (AMP)** was enabled during training.

Mixed-precision training performs suitable computations using 16-bit floating-point precision while maintaining critical operations in 32-bit precision. This approach significantly reduces GPU memory usage and accelerates training without compromising numerical stability or model performance.

**The benefits of mixed-precision training include:**
* Faster model training.
* Reduced GPU memory consumption.
* Ability to process larger batches.
* Improved computational efficiency.

A gradient scaler was employed during optimization to prevent numerical underflow and maintain stable training.

---

## 3.9 Evaluation Metrics
Model performance was monitored using several evaluation metrics throughout the training and testing phases:

* **Training Loss:** Measures the prediction error on the training dataset during optimization.
* **Validation Loss:** Evaluates the model's performance on unseen validation data and helps detect overfitting.
* **Training Accuracy:** Indicates the proportion of correctly classified training samples.
* **Validation Accuracy:** Used to monitor convergence and identify the best-performing model.
* **Test Accuracy:** Represents the final classification performance on the independent test dataset.
* **Precision:** Measures the proportion of correct positive predictions among all predicted positives.
* **Recall:** Measures the proportion of actual positive samples correctly identified by the model.
* **F1-score:** Provides a balanced measure by combining precision and recall.
* **Confusion Matrix:** Summarizes the distribution of correct and incorrect predictions for each class.

Using multiple evaluation metrics ensured that the model was evaluated comprehensively rather than relying solely on overall accuracy.

Dropout was evaluated to determine the appropriate level of regularization for the MobileNetV3-Large classifier.

**Table 4.5: Dropout Comparison**

| Dropout Rate | Test Accuracy (%) | Test F1-score |
| :--- | :--- | :--- |
| **0.0** | 95.73 | 0.9575 |
| **0.2** | 95.41 | 0.9550 |
